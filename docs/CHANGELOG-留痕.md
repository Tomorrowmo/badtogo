## 2026-05-29 · D0：立项 → 可运行成品（同一天）

**背景**：目标是做一个"真有用、能商业化融资"的情绪发泄器，本地可直接使用。由单人以"创业公司全角色"方式完成：战略、产品、心理顾问、研发、QA、运营。

### 重大决策记录

1. **品牌定为 BadToGo**
   - 为什么：复用仓库名，语义双关"把坏情绪打包带走"，可双语、应用商店可注册、朗朗上口。

2. **产品核心 = "宣泄 + 循证平复"闭环，而非单纯发泄器**
   - 为什么（关键）：Bushman(2002) 证明单纯发泄会**抬高**愤怒；只做发泄既无效也不道德、更无法商业化。加入强制平复（呼吸）环节，是把"玩具"变"工具"的护城河。依据见 `02-产品设计与心理学依据.md`。

3. **用"发泄前/后情绪打分"作为疗效度量**
   - 为什么：既给用户即时正反馈（看见自己变好 → 留存），又是融资所需的"有效性证据"，还是数据资产。一举三得。

4. **技术选型：纯前端、零依赖、零构建、本地优先**
   - 为什么："可直接打开使用"+"隐私零上传"是硬约束。Web Audio 实时合成音效、Canvas 做粒子、localStorage 存数据 → 无任何二进制资源、完全离线、包体极小、跨平台。

5. **隐私设计：宣泄文字绝不落盘/上传，情绪记录只存本机**
   - 为什么：心理数据极敏感，多家心理 App 因数据问题被监管/媒体批评。隐私既是伦理底线，也是 B2B/EAP 销售卖点。

6. **商业模式：C 端 Freemium 订阅 + B2B/EAP 双轮**
   - 为什么：免费核心攒口碑与数据，付费点建立在已验证有效的功能上；B2B 客单价高、且本地优先正中企业合规关切。详见 `01` `03`。

7. **加入伦理红线与危机求助引导**
   - 为什么：明确"非医疗诊断"、提供求助热线，既是伦理责任，也是投资人尽调必查项。

### 交付与验证（作证）

- 产物：`index.html` / `styles.css` / `app.js`(29.5KB) / `manifest.webmanifest` / `icon.svg` / `server.mjs`，文档 4 篇。
- 验证手段：
  - `node --check app.js` → 语法通过。
  - `selfcheck.mjs` → 37 个 DOM id / 12 屏导航 / 资源 / 关键实现交叉检查全过。
  - `runtime.test.mjs`（jsdom 端到端）→ **21/21 通过**：完整走通 首页→命名→砸碎→呼吸→复盘→保存→趋势→分享卡，数据正确写入 localStorage，降幅计算正确，运行期 0 个 console.error。
  - `server.mjs` 实测：`http://localhost:5173/` 及全部资源返回 **HTTP 200**、MIME 正确。

**结论**：D0 当天交付一个可直接运行、循证、可验证的成品，达成路线图 P0。

## 2026-05-30 · P1：离线 PWA + 漏斗指标 + 阿里云部署包

**背景**：老板拍板进 P1 并指定**部署到阿里云轻量应用服务器**（而非 Vercel/Cloudflare）。

### 重大决策记录

1. **加 Service Worker，做成可离线、可安装的真 PWA**（`sw.js`，缓存优先 + 版本化清理）
   - 为什么：情绪急救工具要"随时打开就能用"，离线可用 + 可加到主屏幕 = 更像 App、留存更好、断网也能发泄。

2. **新增本地匿名漏斗指标"闭环完成率"**（开始发泄 vs 完成保存，纯本地不上传）
   - 为什么：融资要的核心漏斗证据。配合已有的"情绪分下降率/平均降幅"，构成"有效性 + 完成率"两大可量化卖点。坚持本地存储，守住隐私承诺。

3. **部署改用阿里云轻量服务器：nginx 静态 + HTTPS（Let's Encrypt）为主，Node 直跑为备选**
   - 为什么：老板已有阿里云轻量服务器。nginx 静态托管最稳；**麦克风(吼)功能需要 HTTPS**，故必须配域名 + 证书，方案手册据此设计。Node 直跑(systemd) 作为不配域名时的快速验证备选。

### 交付与验证（作证）

- 新增产物：`sw.js`、`deploy/nginx-badtogo.conf`、`deploy/deploy.sh`、`deploy/deploy.ps1`、`deploy/badtogo-node.service`、`deploy/DEPLOY-阿里云.md`。
- app.js：注册 SW、漏斗计数 `bumpStart/completionRate`、趋势页新增"闭环完成率"卡片。
- 验证：`npm test` → 静态检查全过 + jsdom 端到端 **23/23 通过**（含新增漏斗断言）；本地服务器 `sw.js` 返回 200、MIME 正确。

### 待老板提供（我无法代办的部分）

- 服务器公网 IP、SSH 登录方式、一个域名、域名解析到该 IP。
- 备齐后：本地跑 `./deploy/deploy.ps1 -RemoteHost root@<IP>` 即可上线；或把临时 SSH 方式发我，我远程执行。

**结论**：P1 工程与阿里云部署包就绪，达成"一条命令即可上线"。剩下只差服务器凭证这一步。

## 2026-05-30 · 🚀 正式上线（阿里云轻量服务器）

**事件**：BadToGo 首次公网上线，地址 **http://39.96.207.137:9000/**。

### 决策与执行记录

1. **复用本机已授权的 SSH 密钥直接部署**
   - 为什么：本机已配置可直连该服务器的 SSH 密钥，无需再传任何凭证，最省事也不增加密钥泄露面。

2. **选用 9000 端口（而非最初的 8080）**
   - 为什么：该服务器已运行多个其他站点、部分常用端口被占用，故在空闲端口中选了 9000。
   - 隔离保证：BadToGo 作为**独立 nginx server 块**（监听 9000，独立站点目录），**完全不碰** 80 端口的现有站点。已验证：部署后 80 端口原站仍返回 200、内容不变。

3. **接受 http(无 HTTPS) 的功能取舍**
   - 为什么：换端口 + 无域名 ⇒ 无法签可信证书 ⇒ 非安全上下文 ⇒ Service Worker 与麦克风不可用。撕/砸/捶/呼吸/记录/趋势/分享全部正常；吼模式自动降级为"狂点圆圈"。要恢复离线安装与吼模式，后续配域名 + HTTPS 即可（手册已备 `deploy/DEPLOY-阿里云.md`）。

### 验证（作证）

- 服务器本地：`http://localhost:9000` 的 index/app.js/sw.js 均 200；`nginx -t` 通过、已 reload。
- 公网：`http://39.96.207.137:9000/` 返回 200、内容含 "BadToGo"；全部 6 个资源（html/css/js/sw/manifest/icon）均 200。
- 防火墙：阿里云安全组已放行 9000（外网 TCP 可达验证为 True）。
- 无副作用：80 端口原 Vite 站点验证仍正常（HTTP 200、`/assets/index` 仍在）。
- 已清理服务器与本地的临时侦察脚本。

### 待办（恢复完整能力）

- [ ] 提供/购买域名并解析到服务器 → 用 certbot 配 HTTPS（恢复离线 PWA + 吼模式）。
- [ ] 之后版本更新：本地改完跑 `./deploy/deploy.ps1 -RemoteHost <用户@服务器IP>`（脚本默认目标端口/目录已对应）。

**结论**：达成路线图 P1 的"公网可访问"。产品已真正活在互联网上，可分享、可拉新、可开始积累"情绪分下降率/闭环完成率"数据。

## 2026-05-30 · 🔊 上线 HTTPS（GitHub Pages），「吼」功能可用

**事件**：产品上线境外 HTTPS 地址 **https://tomorrowmo.github.io/badtogo/**，麦克风「吼」模式与离线安装首次可用。

### 关键过程与决策

1. **为什么换 GitHub Pages**：用户最看重的「吼」需要麦克风 → 麦克风需安全上下文(HTTPS)。当前大陆服务器是 http，吼用不了。
2. **试过、失败的偏方（重要教训）**：曾尝试在大陆服务器用 `nip.io + Let's Encrypt` 免备案配 HTTPS，certbot HTTP-01 验证被**连接重置**——证实**大陆服务器上未备案域名走 80 端口会被网络层封锁**，纯 IP 能通是因为没有域名 Host。结论：**大陆服务器绕不开备案**；要免备案 HTTPS 必须**境外托管**。
3. **境外托管的硬约束**：Vercel/Cloudflare/GitHub Pages 都需用户**本人账号登录一次**，AI 无法代登录。GitHub Pages 最省事——代码已在仓库，只需用户在 Settings→Pages 把 Source 设为 GitHub Actions（一个开关），其余由已写好的 `.github/workflows/pages.yml` 自动完成。
4. **enablement 坑**：`actions/configure-pages@v5` 的 `enablement:true` 首次失败（GITHUB_TOKEN 无权擅自开启 Pages），用户手动设 Source=GitHub Actions 后，推空提交重触发即成功。

### 验证（作证）

- Actions 运行 conclusion=success；`https://tomorrowmo.github.io/badtogo/` 及全部 6 个资源均 HTTPS 200。
- 安全上下文 ⇒ 麦克风「吼」、Service Worker 离线、PWA 安装 全部可用。

### 取舍与下一步

- 缺点：github.io 在大陆访问偶尔慢。定位为「验证/自测/给朋友试」够用。
- 大规模面向国内：后续走 Cloudflare（稍稳）或正式 ICP 备案 + 大陆服务器；要收钱再注册个体户升级微信小程序。

## 2026-05-30 · 🧭 找到产品之魂：「允许做自己」

**事件**：经过一轮深度战略对话，确立了产品的"为什么"，写成 `04-产品之魂-见自己.md`。

### 核心结论（重大）
- **使命/核心标语：「允许做自己」**。现代人活成了一整个"超我"(应该懂事/情绪稳定/忍)，与真实"自我"断线；那口压抑的情绪就是被超我捂住嘴的自我。产品的价值不是"消气"，是"**允许**你愤怒/委屈/不懂事"。
- **定位升级**：从"情绪发泄器" → **"情绪显影镜 + 出口"**（显影→发泄→平复）。显影是更强的前门，发泄+平复是原释放阀。
- **三重境界 = 三阶段路线图**：见自己(MVP·个人)→ 见众生(社区/共鸣/人传人)→ 见天地(意义/成长)。
- **"显影"设计铁律**：不要求用户自我打分诊断；斜着进、低门槛却能照出状态；像自我发现非指控；照见后立刻给出口。

### 同时沉淀的"冷水"真相（避免情怀替代验证）
够不着愤怒失控峰值(谁都救不了)→打"还堵着的余波"；别要求用户"决定管理情绪"→做成"无聊难受时无脑点开的爽东西"，发泄是副产品；召回靠"在他路上"(人传人/widget/推送/住进微信)；硬件价值是"存在感"非"检测"(生理信号分不清愤怒)。

### 北极星(升级)
有多少人因"被照见、被允许做自己"而**自己再回来 / 主动把它递给另一个正撑着的人**。

> 这份"魂"是给公司定调的文档；后续纠结功能时回看它一句：这功能让用户更「见自己」，还是又多戴一层超我面具？
